# 지시 22 — 대화·읽기 두께 + 어순 이중 출제 제거

## 목표
대화(중간값 2장)·읽기(1장)를 각각 4장 안팎으로 만들고, 63과에서 벌어지는
어순 문제 이중 출제를 끝낸다.

## 작업

### 1. 어순 중복 제거 (먼저)
현재 `buildDialogueBite`와 `buildBossBite`가 같은 `orderWords` 인라인 문제를 각각
가져간다(65과 중 63과 중복). **대화 바이트에 남기고 보스에서 제외**한다 —
어순은 문장 조립이라 대화 맥락 직후가 맞다.
- `buildBossBite`의 BOSS_TYPES에서 orderWords 제외… 가 아니라, **대화 바이트가 실제로
  가져간 correct 목록을 넘겨받아 보스에서 그것만 제외**(대화 바이트가 없는 챕터에선
  보스가 계속 가져가야 하므로).
- 삭제되는 카드가 생기므로 `docs/harness/additive-exceptions.json`에 63건을 등록
  (스크립트로 생성해도 좋지만 reason은 "어순 중복 제거(지시 22)"로 통일).

### 2. 대화 바이트 +2장
대화 라인에서 파생:
- **말한 이 맞히기**: 대화 라인 하나를 골라 "누가 한 말일까요? · Who said this?"
  2지선다(화자 2명). lines의 speaker가 2종 이상일 때만.
- **대화 클로즈**: 라인 중 그 챕터 어휘(extendedVocabulary)가 들어간 문장 하나를
  골라 그 단어를 빈칸으로, 선택지는 같은 챕터 어휘 3개(품사 우선, overrides의
  guessDistractorBans 적용).
두 카드 모두 chat 카드 **뒤**에 붙는다(대화를 읽은 뒤 확인).

### 3. 읽기 바이트 +2장
지문에서 파생:
- **지문 클로즈** 2장: readingText.body의 문장 중 그 챕터 어휘가 든 것 2개를 골라
  각각 빈칸 1개. 선택지 생성은 대화 클로즈와 같은 규칙.
- 기존 read 카드(QA 플립 3개 포함)는 그대로 앞에 둔다.
- 클로즈는 **번역 토글을 이미 본 뒤** 나오도록 read 카드 뒤.

### 4. 보스 바이트 보강
어순을 뺀 만큼 얇아지지 않게, 그 챕터의 미사용 inlineExercises
(errorCorrect·translate·conjugate 중 tap 가능한 형태로 변환 가능한 것) 검토.
**변환이 부자연스러우면 하지 마라** — 보스는 이미 5.5장으로 충분하다.

## 검증
```bash
npm run guard:thin
node scripts/report-density.mjs after-22
```
dev: 아무 챕터 대화 한입(말한 이·클로즈), 읽기 한입(지문→클로즈 2), 보스에서
어순 문제가 안 나오는지.

## 완료 기준

- additive-exceptions.json에 삭제 63건 등록, guard:thin 그린
- PROGRESS 22행 기록
