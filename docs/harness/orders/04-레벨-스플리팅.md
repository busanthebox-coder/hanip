# 지시 04 — 레벨별 코드 스플리팅: 예산 안으로, 그리고 첫 A2 배포

## 목표
34챕터 bites.json이 entry 청크에 정적으로 실려 예산(entry 150kB gzip)을 깨는 상태를
끝낸다. 코스 데이터를 레벨 청크로 나눠 **필요할 때만** 내려받게 하고, guard:full을
그린으로 되돌린 뒤 A2를 처음으로 배포한다.

## 설계 (이대로 구현)
1. `compile-bites.mjs`가 출력 분리:
   - `src/lib/bites-index.json` — 가벼운 코스 지도: 챕터별 {id, number, title, goal,
     level(A1|A2|B1|B2|C1), biteCount, bites:[{id, kind, title, cardCount, canDo}]}
     (level은 챕터 번호 범위로 판정: 1–11 A1, 12–34 A2, 35–56 B1, 57–63 B2, 64–65 C1)
   - `src/lib/bites/{a1,a2,b1,b2c1}.json` — 해당 레벨 챕터의 **카드 전문**
   - 기존 단일 `src/lib/bites.json`도 당분간 계속 생성 (baseline·report-gaps가 읽는다)
2. `src/lib/courseData.js` 신설: `loadChapterCards(chapterId)` — 레벨 파일을 memoized
   dynamic import 하고 해당 챕터의 bites(cards 포함)를 반환.
3. 소비자 전환: Home·Shelf는 bites-index만 정적 import(오늘 카드의 headWord는 index의
   bite title에서 유도하거나, index에 firstWord 필드를 추가해 해결). App의 play()는
   `await loadChapterCards()` 후 BitePlayer에 지금과 같은 형태의 bite 객체를 넘긴다 —
   **BitePlayer·카드 컴포넌트는 수정 금지.**
4. `.gitignore`에 `src/lib/bites/` 추가 (생성물).

## 검증
```bash
npm run guard:full        # 이번 지시부터 이게 기준 게이트
```
가능하면 `npm run dev`로: 오늘 시작→한입 1개 완주, 책장에서 A2 챕터 1개 진입.

## 완료 기준
- guard:full 그린: entry ≤ 150kB gz, 모든 청크 ≤ 220kB gz
- baseline 그린 (bites.json은 그대로 생성되므로 스냅샷 무변이어야 정상)
- **배포**: `npm run deploy` → 라이브에서 A2 챕터 진입 확인, PROGRESS 04행 기록(배포 ☑)
