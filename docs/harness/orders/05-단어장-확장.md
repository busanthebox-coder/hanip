# 지시 05 — 단어장 확장: 커진 어휘를 감당하는 구조

## 목표
단어장이 A1+A2(약 600단어, 이후 65과 전체 ~1,100단어)를 예산 안에서 다루게 한다.
뉘앙스 레이어(단어당 수 kB)는 목록에 필요 없다 — **목록은 슬림, 깊이는 지연.**

## 작업
1. `extract-wordbook.mjs` 출력 분리:
   - `src/lib/wordbook.json` — 목록용 슬림: {ko, romanization, en, pos, chapter,
     hasDepth(bool), hasCluster(bool)} 만
   - `src/lib/wordbook-depth.json` — ko(+chapter) → 깊이 전체(nuance, explanation,
     commonMistakes, usagePhrases, examples, forms, cluster, ex, collocations, level)
2. WordbookTab: 목록은 슬림 파일로 즉시, `openDetail()`에서 depth 파일을 memoized
   dynamic import 해 병합한 word를 WordDetail에 전달. 배지·필터는 hasCluster/hasDepth 사용.
3. 중복 대표화: 같은 ko가 여러 과에 나오면 목록에는 **한 줄**만, 과 표시는
   "5·6·8과"처럼 병기. 대표 항목의 depth는 깊이가 가장 큰 것. (검색·학습배지 동작 유지)
4. 레벨 필터 칩 추가: A1 · A2 (이후 지시에서 B1·B2·C1 자동 — chapter→level 판정은
   지시 04의 함수 재사용, courseData나 공용 util로 빼라).

## 검증
```bash
npm run guard:full
node -e 'const w=require("./src/lib/wordbook.json").words;const d=require("./src/lib/wordbook-depth.json");console.log("list",w.length,"depth",Object.keys(d).length)'
```
dev로: 검색·필터·중복 대표행("N·M과") 1건·상세 진입(뉘앙스/활용형/짝) 확인.

## 완료 기준
- guard:full 그린, WordbookTab 청크 ≤ 80kB gz (check-budget 출력에서 확인)
- 중복 ko가 목록에 1행씩만, 상세는 여전히 전부 열림
- **배포** 후 PROGRESS 05행 기록
