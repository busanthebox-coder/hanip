# 지시 25 — 신규 챕터 반입 (부모 c10 출하 후 발동)

**발동 조건**: 부모 리포 `korean-core-starter`의 c10 스펙
(`docs/superpowers/specs/v2-upgrade/c10-b2c1-chapters.md`) 진행표에서 챕터가 등록·빌드까지
✅가 된 뒤에만. 부모가 출하하지 않은 챕터를 여기서 먼저 만들지 마라(절대 규칙: 저작 금지).
부분 출하(예: 66~69만) 반입도 허용 — 이 지시를 슬라이스마다 반복 실행한다.

## 목표
부모의 신규 챕터(66+)를 한입 바이트로 컴파일해 책장·그릇·수집·문법 시트에 합류시킨다.
컴파일러 신규 코드 없이(있다면 테스트 선행) 기존 파이프라인 재사용이 원칙.

## 작업

1. **레벨 매핑 전환 (선행, 컴파일 전)**: `src/lib/levels.js`의 `chapterLevel`이 번호 구간
   하드코딩(57-63=B2, 64-65=C1)이다. 66+는 구간이 깨지므로 **명시 테이블**로 전환:
   구간 규칙은 1~65까지만 유지하고, 66+는 `{66:'B2',67:'B2',68:'B2',69:'B2',70:'C1',71:'C1',72:'C1'}`
   테이블에서 읽는다(부모 course.json의 level 필드와 일치해야 함 — 불일치는 중단 사유).
   기존 65챕터의 레벨 판정은 1글자도 변하면 안 된다(levels 테스트에 66+ 케이스 추가).
2. **반입**: 부모 `scripts/rich-chapters/chapter-NN.json` → `data/chapters/chapter-NN.json`
   그대로 복사(부모는 읽기 전용 — 복사 후 SHA-256 대조 로그).
   ⚠️ **부모의 number는 유동적이다** — c10 등록 시 커리큘럼 경로 재부여(apply-curriculum-path)로
   부모 course.json의 number가 통째로 바뀐다(id는 안정 키, 이미 49개가 id≠number).
   한입은 부모 number를 따라가지 말고 **rich-chapters 파일의 id(chapter-66~72)** 기준으로
   반입하며, 한입 자체 번호도 그 id 숫자를 그대로 쓴다(한입 1~65는 불변이므로 충돌 없음).
   부모 course.json상의 새 number와의 매핑은 PROGRESS 특이사항에 기록만 한다. 부모측 감사 기록
   (`v2-upgrade/audit/c10-chapter-NN.json`)이 blocker 0인지 확인하고 경로를 PROGRESS에 남긴다.
3. **컴파일·스크린**: `npm run compile` → 신규 챕터의 생성 카드를
   `node scripts/audit-generated.mjs`로 스크린(스냅샷 diff에 신규 챕터 전체가 잡힌다) —
   blocker 0. 새 문법 패턴(피동 -이/히/리/기 등)이 헌트 추출에 안 잡혀 teach 폴백이 되면
   그대로 두고 개수만 기록(폴백은 결함이 아니라 한계 — RELEASE 관례).
4. **청크 배치**: 66~69(B2)·70~72(C1)는 기존 `b2c1` 청크에 합류(compile-bites의 chunkPick
   `b2c1` 규칙이 level 기준이면 자동 — 번호 기준이면 테이블 반영). `check-budget` 청크 한도
   초과 시 b2c1을 b2/c1로 분할(b1a/b1b 전례).
5. **책장·수집 확인**: dev에서 B2 그룹에 새 챕터 노출, 1개 완주(그릇·수집·문법 시트 3경로),
   단어장에 신규 표제어 합류(extract-wordbook 재실행 결과 수치 기록).
6. **게이트·마감**: `npm run guard:full` 그린(A1 baseline은 변할 이유가 없다 — 변하면 중단),
   snapshot-all은 신규 챕터 포함으로 갱신하되 **재스냅샷 이력 표에 행 추가**(사유: 챕터 반입).
   `npm run deploy` + 라이브 entry 해시 일치 확인. README·RELEASE 수치 갱신.
   PROGRESS 25행 + 커밋 `[order-25] chapters 66-NN ingested` + 푸시.

## 완료 기준
- 반입 챕터 수 = 부모 출하 수, SHA 대조 로그 존재, 신규 카드 blocker 0
- 기존 65챕터 카드 무변경(check-additive 개념 유지 — 신규는 추가만)
- guard:full 그린 · 배포 라이브 확인 · PROGRESS 기록
