# 지시 01 — A2 챕터 반입(12–34): 마른 컴파일과 격차 리포트

## 목표
A2 23개 챕터 원본을 들여와 **수정 없이** 컴파일하고, 추출기가 어디서 폴백하는지
정량 리포트를 만든다. 이 리포트가 지시 02(추출기 확장)의 작업 목록이 된다.

## 전제
`npm run guard` 그린 (아니면 중단하고 원인부터).

## 작업
1. 원본 복사 (부모는 읽기 전용):
   ```bash
   for n in $(seq 12 34); do
     cp "../korean-core-starter/scripts/rich-chapters/chapter-$n.json" data/chapters/
   done
   ls data/chapters | wc -l   # 34 이어야 함
   ```
2. `scripts/report-gaps.mjs` 작성 — bites.json을 읽어 지정 챕터 범위에 대해:
   - 패턴 바이트별: hunt인지 teach 폴백인지, 폴백이면 그 문법 제목
   - guess 카드 중 `sentence`는 있는데 `target`이 null인 것: 단어와 예문
   - 출력: 콘솔 요약 + `docs/harness/audit/gap-report-<범위>.md` 저장
   - 사용법: `node scripts/report-gaps.mjs 12 34`
3. `npm run compile` → `node scripts/report-gaps.mjs 12 34`
4. validate 실패가 있으면 (빈 바이트 등) **데이터를 고치지 말고** 컴파일러의 해당 빌더가
   그 챕터 형태를 처리하도록 최소 수정 (테스트 먼저 — 규약 5).

## 검증
```bash
npm run guard        # 컴파일(34챕터) + 구조검증 + A1기준선 + 테스트 전부 그린
node scripts/report-gaps.mjs 12 34
```

## 완료 기준
- data/chapters 34개, guard 그린 (baseline 무변 — A1만 비교하므로 통과해야 정상)
- gap-report-12-34.md 존재, PROGRESS 01행에 hunt/teach 수치 기록
- **주의**: 이 시점에 guard:full(번들 예산)은 빨간 게 정상이다 — bites.json이 entry에
  정적 포함돼 있기 때문. 예산은 지시 04가 해결한다. **배포 금지.**

## 롤백
`git checkout -- data/chapters && git clean -f data/chapters scripts/report-gaps.mjs`
