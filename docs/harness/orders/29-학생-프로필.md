# 지시 29 — 학생 프로필 + 진도 코드 이전

## 배경과 범위
교실에서 여러 학생이 쓴다. 지금은 진도가 브라우저 하나에 하나뿐이라 공용 기기에서 서로 덮어쓴다.
사용자 결정: **기기 내 프로필 + 진도 코드로 기기 이전**(진짜 계정 동기화는 하지 않는다 —
백엔드·개인정보 처리가 따라오므로 별도 결정 사항).

**정직하게 UI에 드러낼 한계**: 서버가 없으므로 **번호만 입력해서는 다른 기기에서 진도가 살아나지
않는다.** 번호는 이 기기 안에서 사람을 구분하는 이름표이고, 기기를 옮기려면 진도 코드(또는 파일)를
가져가야 한다. 이 사실을 프로필 화면과 이전 화면에 한 줄로 명시하라. 돌려 말하지 마라.

## 측정 (2026-08-08, 이 지시의 설계 근거)
최악 진도(learned 200 · done 696 · collected 271 · srs 400 · bowls 180일):
- 원본 JSON **183KB** → deflate+base64 **75KB** (붙여넣기 불가)
- learned를 단어 키만으로 축약 시 48KB → **9.7KB** (붙여넣기 가능하지만 길다)
→ 코드는 **축약 + 압축**을 반드시 거친다. 목표 3KB 이하, 상한 10KB.

## 작업

### A. 프로필 저장 계층 (`src/lib/profiles.js` 신설)
- 레지스트리 `hanip.profiles-v1` = `[{id, name, code, createdAt, lastSeenAt}]`, 활성 `hanip.active-v1`.
- `code`는 사람이 읽는 4자리(중복 없이 발급). 이름이 같아도 구분된다 — 학생의 "내 번호".
- 기존 4개 키(`hanip.v1`·`hanip.prefs-v1`·`hanip.srs-v1`·`hanip.shelf-open-v1`)를
  **프로필 네임스페이스**(예: `hanip.p.<id>.v1`)로 옮긴다. 스토어들이 이 계층을 통해 읽고 쓰게 하라.
- **마이그레이션이 이 지시의 최대 위험**: 기존 사용자의 진도가 1바이트도 사라지면 안 된다.
  레거시 키가 있고 프로필이 없으면 → 프로필 1개를 만들어 그 아래로 **이동**(복사 후 검증, 그 다음 정리).
  단위 테스트 필수: ①레거시 있음 → 이동 후 값 동일 ②빈 상태 → 신규 프로필 ③이미 마이그레이션됨 → 무동작
  ④레거시 JSON이 깨져 있음 → 진도를 버리지 말고 원본 키를 남긴 채 실패를 보고.
- 프로필 전환은 활성 프로필 기록 후 `location.reload()`로 처리한다(스토어가 모듈 초기화 시 읽으므로
  부분 전환보다 안전하다 — 이 선택의 근거를 코드 주석에 남길 것).

### B. 프로필 UI
- **첫 실행**: 온보딩 뒤 이름 입력(건너뛰면 기본 프로필). 이름은 자유 문자열, 저장은 로컬 전용.
- **설정 시트**: 프로필 목록(이름 + #번호 + 마지막 학습일), 전환 · 추가 · 이름 변경 · 삭제.
  삭제는 2단계 확인 + "이 학생의 진도가 지워집니다" 경고. 활성 프로필은 삭제 불가(먼저 전환).
- **홈**: 현재 프로필 이름·번호를 작게(11.5px ink-3) 표시 — 공용 기기에서 남의 계정으로 푸는 사고 방지.
- 문구는 `docs/tab-contract.md` 언어 정책(영어 메인 + 한국어 소형 보조, 병기 도장 0)과
  `docs/design/STYLE.md`(낙차·색 예산·킬 리스트)를 그대로 따른다.

### C. 진도 코드 이전 (`src/lib/transfer.js` 신설)
- **내보내기**: 활성 프로필의 4개 키 → 축약(아래) → `CompressionStream('deflate')` → base64url.
  접두사·버전 포함(예: `HANIP1.` + 본문). 화면에 **복사 버튼** + **파일로 저장** 둘 다 제공.
  `CompressionStream` 미지원 브라우저는 압축 없이 진행하되 "코드가 깁니다" 안내(기능은 살린다).
- **축약 규칙**: `learned`는 단어 키(ko)만 싣고, 가져오기 시 **컴파일된 데이터에서 카드로 복원**한다
  (전부 로컬에 있으므로 네트워크 불필요). 복원 실패한 키는 조용히 버리지 말고 결과에 개수로 보고.
  `done`·`collected`·`starred`처럼 목록형은 그대로 두되, 크기가 목표를 넘으면 인덱스/비트맵 인코딩을
  검토하라(구현 시 컴파일 산출의 순서에 의존하게 되므로, 버전 필드로 안전장치를 두고 근거를 기록).
- **가져오기는 병합, 절대 덮어쓰기 아님**(부모 리포 `docs/superpowers/specs/v2-upgrade/ws3-progress-backup.md`의
  병합 규칙을 참고해 한입 키에 맞게 적용):
  | 대상 | 규칙 |
  |---|---|
  | done / collected / starred / learned | 합집합 |
  | bowls | 날짜별 큰 값 |
  | srs | 카드별 `reps` 큰 쪽 전체 채택, 동률이면 `due` 이른 쪽 |
  | prefs / shelf-open | 기존 유지(가져온 쪽 무시 — 기기 설정은 기기 것) |
  - **원자성**: 전 키 파싱·검증 성공 후에만 일괄 적용. 중간 실패 시 아무것도 바꾸지 않는다.
  - 적용 전 **미리보기**: "새 한입 12 · 새 단어 34 · 문법 카드 3 추가됩니다" 확인 후 진행.
  - 가져온 코드가 다른 프로필의 것이어도 상관없다(코드에 소유자를 강제하지 않는다). 다만 현재
    프로필에 병합된다는 사실을 미리보기에 명시.
- 단위 테스트 필수: 왕복(export→import 후 상태 동일) · 병합 3규칙 · 깨진 코드 거부 · 원자성.

## 하지 않을 것
- 서버·계정·비밀번호 없음. 학생 이름은 로컬에만 저장하고 어디로도 전송하지 않는다.
- QR 코드 — 최악 payload가 QR 실용 한도(~1KB)를 넘는다. 파일 저장이 그 역할을 대신한다.
- 선생님용 전체 진도 대시보드 — 백엔드 없이는 불가능. 필요하면 별도 결정 사항.

## 게이트
- **컴파일 산출 1바이트 불변** — 시작 전 지문, 종료 후 동일 증명(지시 27·28 관례).
- `npm run guard:full` 그린. 신규 로직은 전부 테스트 선행(레드 확인 → 구현).
- 번들 예산 유지(entry ≤150kB). 압축·전송 코드는 설정 시트처럼 **지연 로드**를 우선 검토.
- dev QA: ①기존 진도 보유 상태에서 갱신 → 마이그레이션 후 진도 그대로 ②프로필 2개 만들어 전환 →
  각자 홈·책장 진도 분리 확인 ③A에서 코드 복사 → B에 붙여넣기 → 병합 미리보기 → 적용 후 합쳐짐
  ④파일 저장·불러오기 ⑤깨진 코드 붙여넣기 → 거부 메시지 ⑥프로필 삭제 확인 흐름 ⑦다크·라이트.
