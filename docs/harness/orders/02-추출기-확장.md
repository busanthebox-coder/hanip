# 지시 02 — 무늬 추출기·추측 타깃 확장

## 목표
지시 01의 격차 리포트를 작업 목록 삼아, A2 문법 제목과 활용형을 컴파일러가 처리하게
확장한다. **A1 출력은 1비트도 바뀌면 안 된다** — 그게 이 지시의 진짜 시험이다.

## 대상 (격차 리포트가 우선하지만, 이미 알려진 어려운 형태)
- 제목 파서(`expandVariants`): `V/A-(으)ㄴ/는데` 류의 중첩 슬래시+선택괄호,
  `V/A-잖아요`·`-거든요`(단일 어미), `못 + verb`(라틴 혼합 — 안+verb와 동형),
  `따라서 / 그러므로`(담화 부사 통짜쌍). `Boundary check`·`Written endings`처럼
  형태소가 없는 제목은 **teach 폴백이 정답** — 억지로 헌트 만들지 마라.
- 추측 타깃(`guessTarget`) 불규칙 활용: 르-불규칙(모르다→몰라), ㄷ-불규칙(듣다→들어),
  ㅅ-불규칙(낫다→나아), ㅎ-불규칙(그렇다→그래). 현재 ㅂ-불규칙·모음융합·하→해는 있다.

## 작업 순서 (반드시 이 순서)
1. 격차 리포트에서 폴백/무타깃 사례를 골라 **실패하는 테스트부터**
   `scripts/lib/compiler.test.js`에 추가 (실제 챕터의 실제 제목·실제 예문 사용).
2. `scripts/lib/compiler.mjs` 수정 — 기존 함수의 계약(반환 형태)은 유지.
3. 각 수정 후 즉시:
   ```bash
   npx vitest run && node scripts/compile-bites.mjs && node scripts/baseline.mjs
   ```
   baseline이 드리프트하면: 그 드리프트가 A1에도 **명백한 개선**인 경우에만
   (예: 듣다 타깃이 생김) 드리프트 목록을 커밋 메시지에 옮겨 적고 `--write`.
   개선이 아니면 수정을 좁혀서 A1에 영향이 없게 하라.

## 검증
```bash
npm run guard
node scripts/report-gaps.mjs 12 34   # before/after 비교
```

## 완료 기준
- A2 패턴 바이트 hunt 비율 **60% 이상** (형태소 없는 제목 제외 시 80% 이상 권장)
- A2 guess 카드의 문장-있는데-타깃-null 건수가 리포트 기준 **절반 이하로**
- 신규 테스트 ≥ 8, 전체 테스트 그린, baseline 그린(또는 이력 기록된 재스냅샷)
- PROGRESS 02행 수치 기록
