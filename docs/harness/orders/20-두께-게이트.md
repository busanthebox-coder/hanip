# 지시 20 — 두께 페이즈 안전장치: additive 가드 + thin 게이트 + 밀도 리포트

## 목표
21·22가 카드를 늘리기 시작하기 전에, **기존 카드가 안 바뀌었음을 기계가 증명**하게
만든다. 이 지시는 컴파일 산출을 바꾸지 않는다(도구만 추가).

## 작업
1. `scripts/baseline.mjs`에 `--all` 옵션 추가 — A1만이 아니라 **전 65챕터**를 같은
   카드키 방식으로 `docs/harness/snapshot-all.json`에 기록. 기존 A1 동작은 그대로.
   **이 지시에서 지금 상태를 `--all`로 스냅샷해 커밋**한다(두께 작업 이전 = 기준선).
2. `scripts/check-additive.mjs` 신설 — snapshot-all.json 대비 현재 산출을 검사:
   - 판정: 스냅샷의 각 바이트 카드키 배열이 현재 배열의 **부분 수열(subsequence)**이면
     OK. 사이에 새 카드가 끼는 건 허용, 기존 카드의 삭제·수정은 실패.
   - 예외 파일 `docs/harness/additive-exceptions.json`:
     `{ "removed": [{ "key": "chapter-05-b8#3", "reason": "어순 중복 제거(지시 22)" }] }`
     — 의도된 삭제만 등록하면 통과. 등록 없는 삭제는 실패.
   - 실패 출력은 baseline.mjs처럼 바이트·인덱스·전/후 키를 최대 40줄.
3. `package.json` 스크립트 추가:
   - `guard:thin`: `npm run compile && node scripts/validate-bites.mjs && node scripts/check-additive.mjs && vitest run`
     (baseline 제외 — 3단계 규칙 C. 21·22는 이걸 쓴다)
   - `guard`·`guard:full`은 **건드리지 마라** (지시 23에서 원복 확인에 쓴다)
4. `scripts/report-density.mjs` 신설 — 21·22의 진척 계기판:
   - 바이트 종류별 카드 수 min/중간/평균/max
   - 문법 바이트 구성(헌트만/헌트+드릴/티치만/티치+드릴) + **문제 ≥2 비율**
   - 본편 1장 바이트 수, 2장 이하 수, 전체 중간값
   - 어순 중복 수(대화 ∩ 보스)
   - 출력: 콘솔 + `docs/harness/density-<태그>.md` (예: `node scripts/report-density.mjs before`)
   지금 상태를 `before` 태그로 저장해 커밋.

## 검증
```bash
node scripts/baseline.mjs --all
node scripts/check-additive.mjs          # OK (자기 자신과 비교)
node scripts/report-density.mjs before
npm run guard:full                       # 산출 불변이므로 baseline도 그린이어야 정상
```
추가로 1회 수동 확인: bites.json의 카드 하나를 임시로 지우고 check-additive가
FAIL 하는지 본 뒤 복구(커밋 금지).

## 완료 기준
- snapshot-all.json · density-before.md 커밋 · guard:thin 동작
- check-additive의 FAIL 동작 확인 완료
- guard:full 그린(이 지시는 산출 무변경), PROGRESS 20행 기록
