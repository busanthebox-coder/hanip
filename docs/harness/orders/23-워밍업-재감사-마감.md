# 지시 23 — 워밍업 비율 + 신규 카드 재감사 + 재스냅샷 + 배포 (페이즈 마감)

## 목표
두께 작업을 마감한다: 워밍업 균형 조정, 새로 생긴 카드만 감사, A1 기준선 재스냅샷,
게이트 원복, 배포.

## 작업

### 1. 워밍업 비율 규칙
현재 모든 오늘-루프 바이트에 워밍업 2장이 붙는다. 21·22 후에도 얇은 바이트가 남으면
복습이 본편보다 길어진다.
- `BitePlayer`(또는 워밍업 산출부): 본편 카드 **4장 미만이면 워밍업 1장**, 4장 이상이면
  현행 2장. 책장 직접 진입은 지시 19대로 0장 유지.
- 단위 테스트 2 (얇은 바이트 → 1장 / 두꺼운 바이트 → 2장).

### 2. 신규 카드 감사
`docs/harness/audit-protocol.md`의 결함 체크리스트를 **새로 생긴 카드에만** 적용
(기존 카드는 additive 가드가 불변을 보장하므로 재감사 불필요).
- 대상 추출: snapshot-all.json(지시 20) 대비 현재 산출의 **신규 카드키** 목록을
  뽑는 `--diff` 옵션을 check-additive에 추가하거나 별도 스크립트로.
- 특히 볼 것: ① 지시 21 클로즈의 "오답이 사실은 정답" ② formTable 클로즈의 의미 없는
  빈칸 ③ 대화 클로즈 선택지 모호 ④ 어순 타일이 유일 정답인지(부사구 순서 자유 문제 —
  1단계 chapter-54 사례 재발 주의: 애매하면 prompt에 "(Start with X.)" 힌트)
- 발견은 `docs/harness/audit/phase3-<범위>.json`에 같은 스키마로. blocker 0까지 수정.

### 3. 재스냅샷 + 게이트 원복
- `node scripts/baseline.mjs --write` (A1) + `--all`(전체) 재실행
- PROGRESS의 **재스냅샷 이력 표에 행 추가**: 날짜 · 지시 23 · "3단계 두께 작업으로
  A1 카드 증가(문법 문제·대화/읽기 클로즈 추가, 어순 중복 제거)" · 사유
- `npm run guard`·`guard:full`이 다시 그린인지 확인. `guard:thin`은 남겨둬도 되지만
  README에 "3단계 전용, 평시엔 guard 사용" 한 줄 명시.

### 4. 최종 검증 + 배포
```bash
npm run guard:full
node scripts/report-density.mjs after
```
게이트(BRIEFING-20 규칙 D):
- 문법 바이트 문제 ≥2 비율 **100%**
- 전체 바이트 본편 중간값 **≥5**, 1장 바이트 **0**
- 어순 중복 **0** · 신규 카드 blocker **0**

dev/Playwright 시나리오 4: ① 2과 문법 한입(문제 2+) ② 대화 한입(말한 이·클로즈)
③ 읽기 한입(지문→클로즈) ④ 얇은 바이트 워밍업 1장.
그다음 `npm run deploy` → **라이브 엔트리 해시 = dist 해시** 확인 → 라이브에서 ①·② 재확인.
