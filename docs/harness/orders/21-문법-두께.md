# 지시 21 — 문법 한입에 문제를 붙인다 (핵심 지시)

## 목표
문법 바이트 236개 **전부**가 "규칙 확인 → 문제 2~4개"로 끝나게 한다.
현재 80%(헌트만 100 + 티치만 89)가 문제 0개다.

## 원칙 (BRIEFING-20 규칙 B)
새 한국어 문장을 **쓰지 마라**. 문제는 그 문법 노트에 이미 있는 재료에서만 파생한다:
examples / formTable(when·add·ex) / drill.items / englishSpeakerPitfall.

## 문제 생성기 4종 (`scripts/lib/compiler.mjs`에 추가, 이 우선순위로 채워 2~4개)

1. **클로즈 드릴 (현행 확장)**: 지금은 "남는 예문 + 변이형 ≥2"일 때만 만든다.
   완화 — 변이형이 1개뿐이면 **오답을 같은 챕터 다른 문법의 변이형**에서 가져온다
   (같은 노트 안에 대안이 없을 때만. 없으면 formTable의 다른 행 `add` 값).
   가져온 오답이 그 빈칸에 실제로 맞으면 안 되므로, 후보가 원문에 등장하면 제외.
2. **어순 타일**: 헌트에 쓴 예문 중 **어절 3~6개**짜리를 골라 order 카드로.
   correct는 원문 그대로, tokens는 어절 분리. (헌트에서 이미 본 문장이라 '적용'
   난이도가 적절하다.) 이미 그 챕터 보스에 같은 correct가 있으면 만들지 마라.
3. **formTable 클로즈**: `ex` 필드가 "밥 → 밥을" 꼴이면 화살표 뒤를 빈칸으로,
   선택지는 같은 표의 다른 행 `add` 값들. 표가 2행 이상일 때만.
4. **함정 판별 (pitfall)**: `englishSpeakerPitfall`의 wrong/right 두 문장을 그대로
   2지선다로 — 프롬프트 "어느 쪽이 자연스러워요? · Which one is natural?",
   정답 right, 해설 explanation. **이건 티치 폴백 89개에 특히 유효** (형태소 추출이
   안 되는 문법도 pitfall은 대개 있다).

## 규칙
- 문제는 항상 **규칙 카드(hunt의 rule 또는 teach) 뒤**에 붙는다. 순서 불변.
- 목표 2~4개. 재료가 부족해 2개를 못 채우면 그 노트를 리포트에 남기고 1개라도 붙인다
  (0개는 실패로 본다 — 리포트에 0개 목록이 남으면 지시 23 게이트에서 막힌다).
- 생성기마다 **테스트 먼저**(실제 챕터 데이터 인용). 특히 1번의 "오답이 실제로 정답이
  되어버리는" 케이스 방지 테스트 필수.

## 검증

```bash
npm run guard:thin                          # additive OK · validate OK · 테스트 그린

```
