# 2단계 브리핑 — "앱스러움" 페이즈 (지시 13~19)

이관(1단계, 지시 01–12)은 끝났다. 콘텐츠는 완결이다: 65과 · 631학습항목 · 2,212카드 ·
간식 12 · 리더 20 · 클러스터 32 · 단어장 718. 2단계는 **콘텐츠를 한 글자도 더하지 않고**
이걸 사이트가 아니라 앱으로 느끼게 만드는 작업이다.

## 2단계 특별 규칙 (1단계 규약 7에 추가)

A. **컴파일 산출 불변.** 이 페이즈의 모든 작업은 UI·런타임이다. `npm run compile`의
   산출(bites.json·bites-index·레벨 청크·단어장)은 바이트 하나 안 바뀌어야 하고,
   따라서 **baseline 재스냅샷은 이 페이즈에서 단 한 번도 없어야 정상**이다.
   재스냅샷이 필요해 보인다면 설계를 잘못 읽은 것이다 — 멈추고 지시를 다시 읽어라.
B. **모든 새 행동은 설정으로 끌 수 있어야 한다.** 소리·햅틱·자동 발음·로마자·테마 —
   지시 13의 prefs 스토어가 유일한 스위치 보관소다. 컴포넌트가 localStorage를
   직접 읽지 마라.
C. **entry 예산 감시.** 설정·온보딩·사운드는 entry 그래프에 들어간다. 현재 entry
   51kB gz, 한도 150kB — 지시마다 check-budget 출력의 entry 줄을 PROGRESS에 적어라.
D. **명칭 현행화.** 사용자 요청으로 학습 유형 명칭이 `무늬 Pattern` → `문법 Grammar`로
   바뀌었다(재스냅샷 이력 참조). 새 UI 문자열은 현행 명칭을 따른다.

## 실행 순서와 의존

13(설정·로마자) → 14(온보딩·시작점) → 15(PWA) → 16(소리·햅틱·피드백) → 17(다크) →
18(스트릭·수집·별표) → 19(SRS). 13이 다른 모든 지시의 스위치 기반이라 먼저다.
15는 독립이라 급하면 순서를 바꿔도 되지만, 캐시 목록에 이후 지시의 산출이 들어가므로
마지막에 SW 캐시 목록 재점검이 필요하다(지시 19 검증 항목에 포함).

## 검증 습관

각 지시: `npm run guard:full` + Playwright/dev로 지시 내 시나리오. 라이브 배포는
지시 15(PWA 첫 배포)와 19(페이즈 마감) 두 번만.
